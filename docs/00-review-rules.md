# Review Rules

The project owner prefers:

- Simplicity over abstraction
- Clarity over cleverness
- Future extensibility over premature complexity

Before introducing:

- New dependency
- New architecture pattern
- New state management solution
- New build tool
- New folder structure

The reviewer must:

1. Explain why.
2. Explain alternatives.
3. Explain tradeoffs.
4. Ask for approval.

No architectural changes may be made automatically.
