# Overview

Technical content creators struggled to repurpose hour-long talks into short-form content due to the massive time sink of manual editing. The system needed to automatically detect key highlights and generate platform-ready short videos without human intervention.

# Architecture

We considered a synchronous batch processing model but rejected it due to unpredictable video generation times causing HTTP timeouts. We designed an event-driven pipeline using AWS SQS and specialized worker nodes (Transcription Worker, NLP Summarizer, Video Cutter). This allowed us to scale workers independently based on queue depth and hardware requirements (e.g., GPU instances only for the NLP phase).

# Challenges

Transcribing technical jargon accurately at low latency was the biggest hurdle. Generic whisper models frequently hallucinated on specific acronyms. We mitigated this by fine-tuning a smaller, faster model on a custom dataset of developer talks, and caching frequent terms in Redis to assist the spell-correction step, balancing speed and accuracy.

# Future Improvements

The pipeline reduced manual editing time by 80% and successfully processed over 500GB of video daily at its peak. If building this again, I would bypass the intermediate object storage (S3) for small, ephemeral video chunks and stream them directly between worker memory spaces using gRPC to further cut down IO latency.
