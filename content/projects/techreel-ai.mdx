# Overview

I am currently developing an automated video generation engine that will be powered almost entirely by **n8n workflows**. The ultimate goal of this project is to take a simple text prompt (or a webhook payload from a CMS) and automatically generate a polished, ready-to-publish short-form reel. 

Instead of writing a custom monolithic backend from scratch, I am utilizing n8n to orchestrate a complex sequence of AI services. Once completed, the workflow will handle everything from expanding the prompt into a script, generating a voiceover, fetching background assets, and combining them into a final video.

# Architecture

The system is designed to rely on an event-driven n8n pipeline hosted via Docker. 

<ArchitectureCallout title="Decision in Progress: Handling Long-Running Renders">
Because video rendering is highly asynchronous and takes time, I am currently evaluating the best way to handle this in n8n. I am moving away from long-polling HTTP request nodes and instead planning to implement a webhook callback architecture. The render service will ping a specific n8n webhook node once the video is finished to resume the workflow.
</ArchitectureCallout>

**The Planned Workflow Steps:**
1. **Trigger**: Will receive a webhook containing the video topic.
2. **Script Generation**: An OpenAI node will draft a 60-second engaging script.
3. **Voiceover**: The script will be passed via HTTP request to the ElevenLabs API for high-quality TTS (Text-to-Speech).
4. **Assembly**: Audio and background visuals will be sent to a rendering service (via FFmpeg or an external API).
5. **Delivery**: The final MP4 will be uploaded to AWS S3, and a Slack notification will be triggered.

# Implementation Challenges

The hardest part of building this workflow right now is designing for **error handling and rate limiting**. 

Because the pipeline will rely on multiple external AI APIs (OpenAI, ElevenLabs, etc.), a timeout or rate limit on a single node could cause the entire video generation to fail. Currently, I am actively mapping out how to use n8n’s built-in Error Trigger nodes and planning to implement exponential backoff and retry logic for all external HTTP requests.

# Future Improvements

Because this workflow is actively being built, my immediate roadmap includes:
- Connecting the n8n workflow to a **PostgreSQL database** to log generation history, track API costs per reel, and manage user prompts.
- Implementing a Sub-Workflow architecture in n8n to cleanly separate the "Scripting", "Audio", and "Video Rendering" phases into modular, reusable components.
- Adding an automatic publishing node (e.g., YouTube API or Instagram Graph API) to post the video directly once generation is complete.
